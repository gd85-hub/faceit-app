**Что есть в приложении** (Next.js 16.2.10, App Router — перед правками читай
`node_modules/next/dist/docs/`, см. `AGENTS.md`):

- `/compare` — сравнение lifetime-статистики двух игроков.
- `/chart` — K/D и ADR двух игроков за последние 20 матчей.
- `/progress?player=X&window=30|50` — один игрок, последние N матчей против
  N предыдущих. Сверху вердикт простыми словами и средний счёт за матч
  (`18 / 15 / 6`), всё остальное (таблица, график) под кнопкой
  «What exactly changed».

**Как устроены данные:**

- Игрок ищется точно: `/players?nickname=X` (`lib/playerService.ts`), без
  `/search/players`.
- Матчи собираются массово: `/players/{id}/games/cs2/stats`, до 3 страниц по
  100 (`lib/matchCollector.ts`, имена полей — `BULK_FIELDS`).
- Архив — один приватный JSON на игрока в Vercel Blob, `players/<id>.json`
  (`lib/matchStore.ts`, `lib/matchArchive.ts`): читаем, дотягиваем только новые
  матчи, склеиваем по `match_id`, пишем с ETag. На файловую систему ничего не
  пишется (Vercel эфемерен). Без Blob данные просто не сохраняются.
- К каждому новому матчу при сборе прикладывается снимок лобби — `skill_level`
  десяти игроков и `collected_at` — из `/players/{id}/history`
  (`lib/lobbySnapshot.ts`). Нигде не показывается, только копится. Ники и id
  чужих игроков не храним — для цели не нужны.
- Сравнение периодов: `lib/periodMetrics.ts` → `comparisonEngine` (принимает
  свой каталог метрик через `definitions`). У каждой метрики есть
  `changeLevel` (`significant` > 2 SE / `likely` 1–2 / `noise` < 1); винрейт —
  разница долей. Вердикт — `lib/periodVerdict.ts`, знак «лучше/хуже» с учётом
  направления метрики — `lib/periodDisplay.ts`. Средний счёт K/D/A — только
  ориентир, значимость считается по отношениям.
- Тесты читают синтетические обезличенные фикстуры `fixtures/faceit/`
  (генератор `scripts/build-fixtures.ts`). У mina616 настоящий `player_id`
  `dbe1f3ef-69d2-4c4c-a435-98f7220b1d28`, остальное выдумано.

**Не проверено вживую — главный риск:**

- `api-fields.md` в репозитории нет, и локально нет `FACEIT_API_KEY`. Имена и
  форма полей `/players?nickname=`, `/games/cs2/stats` (в т.ч. есть ли там
  `Assists` поматчево) и `/history` взяты из знаний об API v4, не сверены.
  Если `Assists` нет, экран сам покажет счёт парой `kills / deaths`, а
  «(K+A) per death» станет «малой выборкой» — но это тоже не проверено.
- Vercel Blob пуст: прод ни разу не записал архив. Причина не выяснена
  (переменные в окружении Vercel? ошибка записи `access: "private"`?).
- Винрейт 37% → 63% с прод-скриншота не перепроверен на живых данных. На
  фикстурах нарезка периодов верна; такая разница на 30 матчах — около 2.1 SE,
  т.е. правдоподобна.
- Различает ли `/players?nickname=` регистр — не проверено.

**Принятые решения:**

- Интерфейс на английском, как всё приложение, хотя ТЗ пишется по-русски.
- Средний счёт показан сразу под вердиктом, а не под раскрытием: это самый
  узнаваемый для игрока способ увидеть разницу.
- «Игра в поражениях» = K/D в проигранных матчах (нужно ≥ 5 поражений в
  каждом периоде), «стабильность» = разброс K/D между матчами.
- Малая выборка — меньше 15 матчей в периоде; такие изменения не называются
  ни ростом, ни падением.
- `SEASON_10_START = 2026-12-09` (`lib/season.ts`) — отметка «сброс Elo, а не
  падение» на графиках.
